# Voice calibration guide

Use this when the user provides a writing sample, brand voice, or strong style preference, and when the piece is voice-sensitive with no sample at all.

## What to match

Match rhythm: sentence length, paragraph length, pace, and how often the writer uses fragments.

Match vocabulary: simple or technical, plain or polished, direct or literary.

Match posture: warm, restrained, bold, skeptical, founder-like, expert-like, friendly, institutional, or editorial.

Match openings and closings: how the voice enters a topic and how it exits without sounding like an assistant.

Match restraint: some brands should be vivid; some should be almost invisible.

Apply the matched voice to the whole deliverable: headlines, subheads, CTAs, button and link microcopy, and captions included, not only the body paragraphs. A founder voice in the body with a corporate CTA underneath it reads as two authors.

## The sample wins over the skill's taste

A provided sample overrides this skill's default preferences wherever the two conflict on style: punctuation habits, formality, sentence length, favorite constructions, regional spelling. If the sample uses a construction the tell catalog lists at cluster bar, and uses it as a genuine habit, keep it.

The sample never overrides the always-bar rules that exist for process, fact, or integrity reasons. Process bleed, invented specifics, inflated certainty, and manufactured proof get fixed in any voice.

## What not to copy blindly

Do not copy typos unless the user wants exact preservation.

Do not preserve unclear structure if the task is to improve clarity.

Do not imitate quirks that hurt trust, such as fake certainty, vague claims, or unsupported proof.

Do not use one house persona for every client. Uniform voice is the failure this skill prevents.

## No sample provided

Default to direct, concrete, and grounded. Use opinion only where the format supports it. Prefer specifics, mechanics, tradeoffs, and proof over mood.

Do not let the default become a house style. A model left to its own taste drifts toward one consistent voice across every project, and generic "sound more human" instructions just swap one uniform voice for another. Pick the register this format and this reader call for, name it to yourself before writing (for example: dry and technical for a security audience, warm and plain for a parents' newsletter), and commit to it for the whole piece.

## Propose voice directions when none is given

When the piece is voice-sensitive, no sample exists, and the user can answer, do not guess. Offer two or three distinct one-line directions and write in the chosen one. Each direction is a posture plus the piece's opening line rewritten in that posture, so the user picks between real sentences, not adjectives:

> 1. Dry, expert, slightly skeptical: "Most onboarding advice assumes your users read. Ours don't, and yours probably don't either."
> 2. Warm, founder-led, plain: "We built this after losing three customers in a month to the same confusing first screen."
> 3. Institutional, precise, no first person: "Onboarding completion predicts second-month retention more strongly than any other metric measured."

Implement only the direction the user picks. When the user asked for immediate output instead, write in the grounded default and name the direction you took in the editorial note, so they can redirect once instead of discovering it late.

## Quick calibration questions

Ask only when the piece is voice-sensitive and the missing answer would change the rewrite.

Useful questions:

- Can you share one paragraph that sounds like you or the brand?
- Should this feel founder-led, institutional, editorial, or sales-driven?
- Are there words or tones the brand never uses?
- Should the copy feel more restrained or more energetic?

If the user wants immediate output, proceed with the grounded default and use placeholders where proof is missing.
